# Data Inventory & Privacy Review (README §20)

> **Important Regulatory Notice:**
> This data inventory and privacy architectural review has been performed with reference to the **Nigeria Data Protection Act 2023 (NDPA 2023)** and the **W3C Verifiable Credentials Data Model v2.0**.
> **NO CLAIM OF FORMAL COMPLIANCE, CERTIFICATION, OR ACCREDITATION** is made with NIMC, NINAuth, NDPC, CBN, or any statutory authority. This project is a testnet and local demonstration architecture utilizing synthetic data only.

---

## 1. Storage Boundaries & Classification Overview

ONEiD enforces strict data compartmentalization:

- **On-Chain (Stellar Soroban Contracts):** Zero personal data. All state and event records are restricted to RFC 8785 canonical salted hashes, Stellar account addresses, status enums, and ledger timestamps.
- **Off-Chain Database (PostgreSQL / Drizzle):** Contains synthetic profiles for demo holders and institution user accounts.
- **In-Memory Cache & Session:** Ephemeral WebAuthn challenge state and signed session identifiers.

## 3. Privacy Design Principles (NDPA 2023 Principles)

1. **Lawfulness, Fairness, and Transparency:** Explicit, selective, claim-level consent is required before any disclosure. Plain-language notices inform the user that consent withdrawal applies to future sharing only.
2. **Purpose Limitation:** Every consent receipt binds the verifier identity and the specific transaction purpose. Presentations cannot be replayed for unapproved purposes.
3. **Data Minimization:** Selective disclosure credentials (SD-JWT VC) disclose only requested attributes without revealing master identifiers (e.g., age verification returns `over18: true` rather than full date of birth).
4. **Storage Limitation:** Off-chain stores adhere to documented TTL schedules defined in `retention.md`.
5. **Integrity and Confidentiality:** Passkey WebAuthn hardware-bound keypairs, strict CSP, SameSite cookies, and salted hashes protect data in transit and at rest.
